# 企业 OA 智能采购与制度问答助手

面向员工采购、报销前的咨询场景，用自然语言查询制度、部门预算、供应商和采购审批链。制度回答展示出处；预算与审批查询对接自建模拟 OA，由代码执行金额与规则判断。

**个人项目 · Python 后端开发 · AI 应用开发 · 云端部署**

[在线演示](https://oa.jacewood.work) · [技术说明与本地运行](docs/technical-guide.md) · [评测记录](docs/day8-quality.md)

> 在线演示需要访问账号，可联系项目作者获取。制度和业务数据均为模拟数据。项目已部署，制度问答的结构化输出稳定性仍在改进中。

## 项目概览

| 项目内容 | 实现情况 |
|---|---|
| 制度知识库 | 50 份模拟制度，按条款切分为 150 条，保留名称、版本、条号与来源文件 |
| OA 工具 | 查询预算、查询供应商、按金额查询审批链，共 3 类接口 |
| 后端开发 | Python、FastAPI、Pydantic、SQLite；接入大模型与向量化 API |
| 部署方式 | Docker Compose + 阿里云 Linux + Nginx，提供 HTTPS 演示入口 |
| 质量验证 | 离线单元测试、24 题开发回归集、人工复核记录、GitHub Actions 工作流 |
| 个人工作 | 完成接口开发、RAG 与工具调用集成、容器化、云部署及评测资料整理 |

## 能解决什么问题

| 场景 | 示例问题 | 处理方式 |
|---|---|---|
| 查制度 | “紧急采购可以跳过审批吗？” | 检索相关条款，核验引用与结论支持关系后回答 |
| 查预算 | “研发部 2026-10 还剩多少预算？” | 查询 OA 预算记录，区分余额为零与记录不存在 |
| 查供应商 | “查询正常的电脑供应商” | 按品类、名称或状态筛选供应商名录 |
| 查审批链 | “采购 8000 元需要谁审批？” | 由 OA 代码规则返回审批人、规则编号与版本 |
| 信息不完整 | “查询剩余预算” | 提示补充部门、月份等条件，再提交完整问题 |
| 制度未覆盖 | “公司允许带宠物上班吗？” | 证据不足时拒答，避免用常识代替企业制度 |

## 关键设计

- **制度回答可以查来源。** 按“第 X 条”组织资料，回答附带条号与原文引用；先校验引文是否来自检索条款，再由模型复核支持关系。保留人工评测，避免把真实引用等同于正确结论。
- **财务规则由代码执行。** 大模型负责识别意图与提取参数，金额处理使用整数分与 Decimal，审批阈值由代码判断，工具结果使用固定模板呈现。
- **错误状态有明确区别。** 参数缺失、预算记录不存在、证据不足、OA 不可用分别处理，并记录请求编号，便于复查问题。
- **完成应用部署与回归配置。** 使用容器服务名进行内部通信，Nginx 提供 HTTPS、演示登录保护与请求限速；配套健康检查、日志、证书续期和数据库备份检查脚本。

2026-10-22 保存的一轮 **24 题开发回归记录**如下，自动检查与作者人工复核的通过数量一致：

| 类别 | 通过 / 总数 |
|---|---:|
| 工具查询 | 10 / 10 |
| 参数澄清 | 4 / 4 |
| 无依据拒答 | 2 / 2 |
| 制度问答 | 1 / 8 |
| **合计** | **17 / 24** |

7 道制度问答返回 `502 invalid_model_output`，未产生有效业务回答，已计为失败。下一步优先补充路由、起草、复核阶段的错误信息，定位结构化输出失败原因并复测。

这些数字来自开发小样本，不能代表生产准确率。本轮服务器版本和模型标签未记录，限制了结果复现；后续评测需补齐。GitHub Actions 工作流已配置，运行状态以仓库 Actions 页面为准。

项目当前定位为个人演示：使用模拟制度与模拟 OA，仅支持单轮、单动作、人民币查询；不执行审批写入或预算扣减，也未实现企业账号与角色权限体系。
